# Agents

Agents are **not** defined in this repository. They live in a single global
location shared by every project on this machine:

    $CONFIG_DIR/agents/

`$CONFIG_DIR` defaults to `~/.claude` when unset. Resolve it as:

```sh
CONFIG_DIR="${CONFIG_DIR:-$HOME/.claude}"
ls "$CONFIG_DIR/agents/"
```

Each agent is a single markdown file, `$CONFIG_DIR/agents/<name>.md`, with YAML
frontmatter carrying `name` and `description`.

## Available agents

| Agent | Purpose |
| --- | --- |
| `db-designer` | Database schemas, ERDs, migrations, ORM entities |
| `java-engineer` | Java backend features — API endpoints, data processing |
| `pr-tracker` | Pull request deployment status after merge to master |
| `python-engineer` | Python backend features — API endpoints, data processing |
| `qa-writer` | Manual test plans, test cases, checklists |
| `reviewer` | Review implementation against `.ai/` plans and best practices |
| `tester` | Execute `qa-writer` test cases and report results with evidence |

Treat this table as a summary. `$CONFIG_DIR/agents/` is the source of truth —
list that directory rather than trusting this file when they disagree.

## Supporting references

Agents that read reference material load it from:

    $CONFIG_DIR/agent-references/<agent-name>/

Held outside `$CONFIG_DIR/agents/` on purpose: reference files carry no
frontmatter, and nesting them under the agents directory would make the loader
try to parse them as agents.

## Rules

- Do **not** add agent definitions under `.ai/agents/` — a per-project copy
  drifts from the global set. This file is the only thing that belongs here.
- To add or change an agent, edit `$CONFIG_DIR/agents/<name>.md`. The change
  applies to every project immediately.
- Project-specific context belongs in `.ai/` (features, workflows, memory), not
  in the agent definition.
